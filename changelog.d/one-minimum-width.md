### Changed

- Render, `measure`, `canDraw` and React name the same minimum width for a width alone, found by one search over the layouts render draws, its steps after a refusal included (authored column widths giving way, type stepped down on a slide, the next smaller type class). `minWidth` is the narrowest width from which every wider width draws in full mode, `compactFloor.width` the narrowest from which every wider width draws at all, and a size refusal names the width at which the request starts to draw under its own `belowMinimum`. Before, these could differ: a table at 280 px was refused with 1208 px in render and `canDraw`, `measure` said 1057 px, and the table drew from 1024 px. `measure` named a `minWidth` where render falls back to compact (a two-panel bar table: 367 px, full from 451 px), a `compactFloor` above the width a column draws from (280 px for a slide column that draws from 125 px), and no `compactFloor` for a waffle that draws compact. A table's and a dimswitch's refusal now reads like every other type's ("needs at least N px of width"). A dimswitch refusal names the height drawn at that width, where `measure` named the height of the folded card (at 280 px: 551 px, before 224 px). CLI `measure` no longer draws each advised size a second time; it confirmed every size the core named. A chart that draws keeps its output.
