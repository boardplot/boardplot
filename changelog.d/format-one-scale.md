### Fixed

- An authored format with a scale word holds all value labels of one chart to one scale and one decimal count. Before, each label decided for itself, so 1000, +50, −20 and 1030 under `'1.2k'` printed 1.0k, +0.1k, −20.0 and 1.0k: +50 read as about 100, −20 left the thousands, and the labels did not add up. Under `'1,234k'` they printed 1k, +0.1k, −0.02k and 1k. Both now print 1.00k, +0.05k, −0.02k and 1.03k, as `'1.23k'` always did: the decimals rise for every label until each value shows its first digit. A scale above every value steps down for the whole chart. A chart with a value more than 1,000 times below the scale draws as before, so 20 can stand beside billions. A nonzero value still never prints as 0. This covers waterfall, column, line, bar, bullet, choropleth and tile map keys, cohort, combo, funnel, heatmap, mekko, pareto, slope (diverging too), variance and waffle, and a series `format`. A cell `format` and a bartable panel's format keep their own scale. There is no option to bring the old look back. No golden changes.
- The warning `format-hides-values` says what the chart prints, for example "format '1.2k' cannot show -20 near its size, so the chart prints every value with 2 decimals: -20 as −0.02k". It also fires when the decimals rise and no value would have printed as 0. Before, it named only values that round to 0 and claimed a text such as 0.0k that the chart never drew.
