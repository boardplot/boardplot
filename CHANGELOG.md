# Changelog

Boardplot is in 0.x: options and output can change between minor versions. Each release lists its changes here.

## Unreleased

### Changed

- An authored number format now prints every value as its example reads: the sign form, prefix, suffix, scale word, and decimals or significant figures stay as written. Under `"$1.2M"`, 4 prints `$0.0M`, not `$4.0`, and under `"$@@@M"`, 999,960,000 prints `$1,000M`, not `$1.00B`. To get the earlier text, write the example that the warning `format-hides-values` proposes, such as `"$1.2"`.
- This holds for the chart, series, row, column, cell and axis formats, and for totals, subtotals and calculated table rows and columns: a total no longer takes more decimals or another scale word than its example. A German or French chart still prints the scale in its own words, and `scale`, `options.magnitude`, `fitFormats`, `options.signs` and the unit in a table head keep their effect.
- A negative value that rounds to zero prints the example's zero without a sign: −0.02 under `"+1.0%"` prints `0.0%`, and the chart warns `format-hides-values`.
- Axis ticks and statistics print as before. Ticks take their digits from their spacing, and a mean, median, spread, band bound or rate takes up to one decimal more than the example where it needs one. A unit-only format such as `"$M"` or `"%"`, and a chart without a format, print as before.
- A chart prints the same text wherever and whenever it is drawn: alone or after other charts, as SVG or PNG, in the React components (including the table and the dimension switch), in its hover card, data table and reading, and when its exported document is drawn again. An exported document keeps a unit-only format such as `"$M"` as written.
- `format-hides-values` now covers every chart type and every place that takes a format. It fires where a nonzero value prints as the example's zero, or where different values of one series, table row or table column print one text, and it names the format's path. Its patch keeps the example's style, tries the scale word that fits and then more decimals, and is checked by drawing the chart with it; where no patch works, the warning says so.

## 0.58.2

### Fixed

- `anchors.baselines` on a grid now aligns baselines only between panels that cover the same rows: `"all"` aligns as `"row"` does, and `"column"` aligns nothing, because stacked plots do not share a baseline. With `"column"`, and with `"all"` over more than one row, `render` and `measure` could refuse the grid, run out of memory or name a size at which it did not draw. With `"all"`, a panel that spans rows no longer aligns with a panel that covers only some of those rows.

## 0.58.1

### Changed

- Cohort tables (`variant: "pure"` and `"stepped"`) line up the rates of each period column, the total row included, on one right edge, so digits and decimal points sit under each other. The column of figures stays centred under its period head. Each rate was centred on its own width before. To bring back the old look, set `options.columnOverrides.periods.align: "center"`.

### Fixed

- `render` and `measure` now return on some grids with `anchors.baselines` where they did not return or the Node process crashed, such as a grid whose panels are stacked in one column. The size search of a refused layout follows the size that each refusal asks for. It now stops once that size grows past a bound set from the first refusal and the frame, and refuses the grid with `label-collision`. Before, `measure` also named a minimum height from about 15,000 px to 2 × 10^47 px on some of these grids, where the chart does not draw either. A `measure` refusal for a reason other than size now names a minimum height above both the refused frame and the chart type's declared minimum height only where a layout of the chart draws at that height. Some grids with `anchors.baselines` are not fixed: on some, `render` and `measure` still run out of memory, and others are refused with `size-below-floor` and a minimum height of about 10^11 px, where the chart does not draw either.
- A long daily line with `window: { decimate: "none" }` keeps its axis readable: the month ticks the engine picks for a long day row thin to the labelled ones when they would sit closer than 2 px. 100,000 daily points drew about 3,300 ticks that merged into a solid bar. An authored `categoryAxis.dateTicks` keeps every tick as before.
- On a canvas with a fixed height, a choropleth's automatic value table goes under the map only when the map keeps its full natural height. Before, the table could shrink the map to a thumbnail although the map alone printed every value. When the map without the table loses no value, the table is now left out, as the `valueTable` reference describes.
- Annotations written at a chart's top level, or at a grid panel's top level, now meet the same chart-type rules as `options.annotations`: a gantt badge label longer than 3 characters, gantt event `items`, a badge on column, combo or line, and duplicate annotation ids are refused at the authored path. The fix of an over-long badge label now switches `labelPlacement` to `'top'` instead of removing the label.

## 0.58.0

### Added

- `highlight` accepts category IDs on one plain data line without a fan. For example, `{ "options": { "highlight": ["w5"] } }` enlarges W5's marker and paints its marker and value in the theme's focus ink while the line keeps its paint and width. The marker size follows the theme's focus-to-data stroke ratio. Existing series emphasis, authored marker shapes and fills, and explicit label suppression remain effective. Reference series do not count as data lines. Several data series, area, stacked, bump and fan forms still warn once for unsupported category IDs and leave the chart unchanged. Series IDs take precedence. Remove the category ID from `highlight`, or use `{ "options": { "highlight": [] } }` when it is the only selection, to restore the ordinary marker and value.
- Theme key `marks.arrow` sets the look of every annotation arrow: `head`, `headWidth`, `stroke`, `tipGap`, `tailGap` and `minShaft` in px, and `style`. For example `{ "marks": { "arrow": { "head": 10, "tipGap": 8 } } }`.
- A drawn `arrow` whose shaft is shorter than 24 px warns `arrow-short`. A callout with `arrow: true` that finds no seat with room for a 24 px shaft draws without the arrow and warns `callout-arrow-no-room`.
- A callout with `arrow: true` can also stand over or under its point, so `preferSide: "above"` or `"below"` keeps its arrow.
- Waterfall option `bracketRow`: `"shared"` (default) or `"span"`.
- `delta` takes `mode`: `"absolute"` (the default) prints the value difference, `"relative"` the percent change from `vs`, for example `+36%`, and `"both"` the two together, `+149 (+36%)`. A percent mode with a `vs` of 0 warns `ref-zero`.
- `diff` takes `mode: "both"`: the value difference with the percent change from `from` beside it, `+149 (+36%)`. A `from` of 0 warns `ref-zero`.
- Bar value labels take one chart-wide `options.labelPosition`: `auto`, `center`, `insideEnd`, `insideBase` or `outsideEnd`. The inside end and base follow the bar edges farther from and nearer zero. Floating bridge steps fall back above the bar, or to the right on a horizontal bridge, when the requested seat is too small or blocked. Existing pins and automatic placement keep their meanings. Stacked variants and integrated variance support inside positions and refuse `outsideEnd`.
- A live chart with `notes.pointer: false` that leaves author notes out of its footer warns `notes-left-out`. The warning counts the notes, names the `notes.maxLines` that prints them, and carries a patch that removes `notes.pointer: false`. Before, the notes appeared nowhere and `onWarnings` was empty. The React table now also reports its footer's own warnings, as the SVG table does. Author notes of a kind that `notes.show` switches off do not count. Static output prints every note and stays silent.
- Column option `referenceTick.position`: `"behind"` (default) or `"front"`.
- `options.labelOffsets` moves a label by a set distance from the seat it would take, keyed by label id, such as `{ "annotation:callout-2": { "y": 40 } }`. A blocked move keeps the label in its seat and warns `label-offset-blocked`. An unknown id warns `label-offset-unknown`. A value moved off its own bar prints in page ink with a halo.
- Four drawing annotations place text and simple shapes on data positions: `text`, `line`, `arrow` and `box`. A point is an anchor or `{ categoryId, value }` in axis units. A value outside the plot warns `bad-anchor` and draws nothing. A stretch that would cross text is cut around it and warns `draw-crosses-text`.
- A `line` or `arrow` end may be `{ "annotationId": "<id>" }` of a `text` annotation. It attaches to the nearest edge of that text at every width.
- A `box` corner given by category takes the outer edge of the category's band, so the box wraps whole bars. A box may span one category.
- A value moved off its bar leads from its own bar's top or end into its text. A move that sets a value beside its bar is refused with `label-offset-blocked`. A value moved within its bar keeps 4 px from the bar's edges.
- Grid option `variancePosition` for category tiers: `"above"` (default) stands the variance tiers over the column panel, with the category labels at the bottom of the exhibit; `"below"` stands them under it in authored order, with the category labels between the columns and the tiers. The default is unchanged. Before, a variance tier listed first to stand under the columns took the category labels and grew the grid to several times its height.
- `docs/reference/warnings.md` lists every warning and refusal code a chart can return: its severities, whether a site returns a `fix`, and the chart type or shared file that returns it. `npm run docs:build` writes it from the source; the manual links it.
- `npm run check:warning-codes`, also in `npm run check:ci` and CI, fails when a code breaks the telemetry code pattern, when the render tool text, the skill or the manual names a code that does not exist, or when a code has two severities without a stated reason.

### Changed

- Point values on one plain data line now prefer left of the first finite point, above a strict local peak, below a strict local trough and right of the last finite point. The new `pointLabelSide: "shape"` default reserves space for endpoint values beside their points only where the plot can spare it. The reserve is not used when the centred end room cannot print every category name, or when the reserve would print the category names differently. If a layout with the reserve hides any label, the chart is laid out again with the centred end room. It keeps the reserve only if every label of the centred layout still prints. Flat plateaus keep the previous preference. Reference series do not count as data lines. Several data series, area, stacked, bump and fan forms keep their previous placement. The label solver still checks collisions and honours `labelPlacements` pins. A reference line through a preferred seat blocks that seat. The solver uses the next candidate without cutting the reference line around the value. To restore the previous candidate order and endpoint reserves, use `{ "options": { "pointLabelSide": "auto" } }`.
- Shaded-band names now try seats within the plot before seats beyond it. The plot includes reserved annotation headroom. Seats within the plot keep their previous order, so a clear name above a band stays there. A name that would leave the plot can instead wrap inside. Previously, the one-line `aboveBand`, `aboveBandEnd` and `aboveBandStart` seats preceded extended inside seats even when outside the plot. To restore the previous outside seat in the narrow maintenance example, use `{ "options": { "labelPlacements": { "annotation:maintenance": "aboveBandEnd" } } }`. For the same band as the first annotation without an explicit ID, use `{ "options": { "labelPlacements": { "annotation:band-1": "aboveBandEnd" } } }`. Use the band's own annotation ID and previous slot for other bands. Pins keep their previous candidate order and collision fallback. Bracket bands keep their placement order.
- `boardplot_describe` in compact detail names the accepted shared options and defines value cells and annotation anchors where a type uses them, so a known type needs no `boardplot_list` call. Full detail keeps the type's own fields with complete descriptions; shared options stay names, and `path` returns one in full.
- MCP output schemas declare the chart reading, `severity` and `displayPath` on findings, and the font tables. A file-row error on a category chart now names its source cell in `displayPath`, such as `rowsFile row 1.v`, and its message counts rows from 1, as the other row errors do. Before, it printed `rows[0].v`. A repeated category and series pair names both rows from 1 too, as `(rows 1 and 2)`; it printed `(rows 0 and 1)`. Tool names and arguments stay the same.
- The dimswitch describe example shows a child measure, a computed CAC ratio and the member level.
- The chart skill sends a ready spec straight to render and a known type to compact discovery, and no longer asks for the manual before the first chart. Its references are packaged beside it, so every link resolves in the marketplace and offline ZIP installs.
- Every annotation arrow follows one standard: a drawn arrow, a callout arrow, a CAGR bracket and growth arrow, a difference, a link, a gap bracket and a band bracket. The head is filled, 8 px long and 7 px wide. The shaft stays the thin `stroke.rule` line; `marks.arrow.stroke` sets its width, for example `1.5` for a shaft as heavy as the data marks. An arrow to a data point stops 6 px off its marker's edge, and its tail starts 4 px off its text. A callout arrow seats its text at least 24 px of shaft from its point, a difference from a line point starts 6 px off that point's marker. A CAGR bracket keeps the reach of its legs, so its plot keeps its height: the larger head shortens the visible shaft to about 9 px. A difference or bracket still touches its level guide. Before, heads were 4 to 10 px by kind (callout 4, link, bracket and difference 5, drawn arrow 6, growth arrow 10), a tip sat on its point and no shaft had a minimum. The theme patch `{ "marks": { "arrow": { "style": "compact" } } }` brings back that look.
- A disclosure asked for only by `methodNote: true` or an authored `notes.placement` now prints within the line budget, after the author notes, like a method note. What does not fit goes to the notes list, and "+N notes" counts it. Before, such a disclosure printed outside the budget in a live chart, so a React table with `notes.placement: "frame"` and five author notes printed two of them, three engine notes and "+3 notes". Outside the budget print only a required credit, an author note or a disclosure a drawn mark points at (the rank key, a numbered note on a cut name), and a disclosure whose kind the author lists in `notes.show`. The option patch `{ "notes": { "show": ["note", "method", "disclosure"] } }` brings back the old footer. Static SVG and PNG output does not change: it prints every enabled note. A chart that hands its options to another chart type (cohort, histogram, likert, pareto, pyramid, pvm) treats `methodNote: true` the same way.
- On a bar chart, a `diff` between two categories of one series now rides in the shorter bar's row, with the number in a break of the arrow's shaft. Before, the arrow ran between the rows and the number stood beside it, often next to another bar. The annotation field `placement: "label"` brings back the old form.
- Waterfall: the step brackets of one bridge now stand on one shared row, the lowest row that clears every bracketed span and its values. A single bracket stands right above its own steps and their values. A bracket moves to the top row of the plot when its seat is taken. The plot keeps the room for the top row only where a bracket stands there. Where every bracket stands on a row below, the empty band under the subtitle goes back to the plot: an automatic-height card gets shorter, and a fixed card gets a taller plot. Before, every bracket stood in one row at the top of the plot.
- `bracketRow: "span"` on the waterfall stands each bracket right above its own steps and keeps the full room above the plot. No option brings back the top row of 0.57.0 for every bracket.
- The manual and the bullet option description now say that a bullet row keeps its natural 44 px pitch in a frame taller than the rows need, and that the extra height stays empty below the chart.
- Series that share a `colorRole` now draw in distinct steps of that role's colour in line, stacked area, combo, funnel, mekko, butterfly, pyramid, bartable (segments and row groups), waffle, scatter groups, treemap groups and waterfall segments, as column, bar and dot already did. The key shows the same steps. Before, all such series drew in one identical colour, and several of these types warned `series-indistinguishable`. A slope chart steps them only when it draws a key, because its endpoint labels name the lines. Gantt bars, sankey nodes and status cells keep one colour per role, because there the role judges one item and its position names it. Waterfall segments with one label and one role still share one step and one key entry.
- To bring back the earlier look, give each series its own `fill`: `{ "id": "north", "colorRole": "good", "fill": "#0FA060" }`.
- A column value under a reference tick that sits just over the column's end prints inside the column's end. Before, it moved above the tick, where it read as the plan's value. A pin brings back the old seat: `{ "labelPlacements": { "point:<series>:<category>": "outsideTopShifted" } }`.
- A callout, a note or a delta on a column stands straight above it, over the column's printed value and over a reference tick, without a leader. Two or more on one column stack there. Before, a note over a column whose value printed above it moved beside the column on an S-shaped leader, and a second note on the same column went beside it too or was hidden. `preferSide: "left"` (or `"right"`) on a callout brings back the seat beside the column.
- A reference value beside its tick no longer stands over a neighbouring column, where it read as that column's plan. Where only such a seat was free, the value now goes to the notes.
- A column chart whose category names would be cut on the rotated 45° row now draws as horizontal bars, as it already did when the names could not rotate at all. The same conditions apply: an open height or a pinned height that holds every row, and only settings a bar draws as a column does. The bars must also need at most a quarter more height than the columns; a chart with many more rows keeps its columns. Before, every rotated name was cut with an ellipsis and kept its full text in the SVG title only. To keep the column, pin a height that cannot hold one row per name, or widen the canvas.
- CLI `--columns` also takes a JSON object, the same one the MCP tool's `columns` argument takes: `--columns '{"category":"month","series":"segment","value":"revenue"}'` draws the same chart as `--columns category=month,series=segment,value=revenue`. A JSON value that is not an object of strings is refused with `invalid-argument`.
- On a column chart, a `diff` or `delta` between the totals of two columns that are not neighbours runs as the growth bracket over the columns, the form a `cagr` takes, with the difference on its arm. Before, a `diff` stood as an arrow in a free gap between the two columns with its number beside it. On a narrow canvas no gap was free, the arrow moved beside the last column, and its number was hidden (`label-hidden`, `values-in-note`). A `delta` printed its number over its column. `placement: "label"` brings back both older forms: `{ "kind": "diff", "from": "jan", "to": "dec", "placement": "label" }`.
- In status, waffle and histogram charts, a claim's `displayed` is now the text printed on the chart, and the words that stood there move to a new optional `description` on the claim record and on its `reading.derived` entry. A status count prints nowhere on the chart: `displayed` was `"Rate cut 254"` and is now `""`, which the reading shows as `"Not displayed"` with `visible: false`. A waffle cell count also prints nowhere: `displayed` was `"30% = 30 of 100 cells"` and is now `""`. A histogram bin was `"[0, 250)"` and is now the count its label prints, such as `"76"`, or `""` where no label prints the count, such as on a percent axis. Read `description` for the old text. Charts draw as before.
- A funnel prints its segment values and stage totals at one magnitude: the largest step at which the smallest value still prints as 1 or more, while the largest keeps at most four digits. A value that prints 1,000 or more at that magnitude prints whole. So `1,180M · 590M · 290M · 140M` instead of `1.18B · 590M · 290M · 140M`, and `1,200k · 300k · 45k · 8k` instead of `1.2M · 300k · 45k · 8k`. A set that no single magnitude fits, such as `2.4M · 86.0k · 4.1k · 310.0`, keeps one scale per label as before, and so does a funnel with an authored format on the chart, a series or a cell. Decimals and conversion rates print as before. No option or theme patch brings back the old look for every chart. A cell format per value restores the old text exactly, for example `"values": [{ "number": 1180000000, "format": "1.23B" }, { "number": 590000000, "format": "1M" }]`.
- Under a comma decimal mark (`locale.decimal: ","`), the hover record of a chart value now carries the text the chart draws, such as `0,042` or `1.180M`. Before, the record read the marks by guess, lost that text and the hover printed the source number.
- A setting a type accepts but cannot draw now warns `option-ignored` and is removed, with a sentence on what it does on the types that have it: `focus` and `labelDensity` on table and dimswitch, `highlight` on bartable, `valueAxis` on grid, treemap and waffle, and `topN.threshold` on butterfly, mekko and pie. Before, the chart drew the same and the request passed without a warning. `valueAxis.break` on a grid stays refused. `describe` lists these settings as ignored, and `describe` of one of these paths says the type ignores it.
- A bar table panel in a grid with `highlight` now takes the grid's shared series colours, so a series keeps one colour across panels. Before, the setting left the panel out of the shared colour assignment: with two bar table panels whose series run a, b and b, a, series a was dark in the first panel and blue in the second. Remove `highlight` from such a panel to keep the new look; there is no setting that brings back the old colours, because they came from a dropped setting.
- A value of one of these settings that the schema refused before is now removed with the same warning, and the chart draws. Example: a pie with `topN: { n: 1, threshold: "oops" }` was refused and now draws with `option-ignored` on `topN.threshold`.
- The MCP server no longer loads the 1.9 MB font reader for PNG output at start: it loads it before the first `boardplot_render` call whose `format` or `outDir` asks for a PNG. The CLI loads it only for `--format png` or an `--out` file that ends in `.png`, not for any argument that contains "png". PNG bytes are unchanged.
- The default Likert ramp now clears its own adjacent-colour floor, so it no longer warns `series-adjacent-similar`. Two neighbours moved. The neutral grey keeps 12 OKLab from the mildest option beside it on a light page too, not only on a dark page: in `bridge` it is `#d5d9e5`, before `#d4d8e4`. Where no neutral is drawn between the two sides (`neutral: 'exclude'` or an even scale), the mildest good option steps until it keeps 12 OKLab from the mildest bad one: on a seven-point scale with `neutral: 'exclude'`, it is `#9fb8df` in `standard-dark` (before `#acc6ef`), `#aeccf9` in `bridge-dark` (before `#b4d0f9`) and `#a1b7dd` in `notation-dark` (before `#adc4ed`). Each colour moves only as far as the floor needs and never below the mark visibility floor, and a ramp that cleared the floor draws as before. No option brings back the old colours.
- `measure` of the same chart at another width, also from a new copy of the spec, reuses the widths that an earlier `measure` of it already laid out. Trying widths for one chart no longer lays out every narrower width again. The answers do not change.
- A grid with an automatic height no longer drops a callout or note that has no seat in a panel. It grows until the note seats: at 360 px, an actual-vs-plan grid with a callout on one year grows from 296 to 343 px and keeps the callout. A lone callout or note on a column wraps on two lines straight above it, over its value and a reference tick, before it moves aside on a leader. A pinned `size.height` brings back the old height, with the note in the notes list.
- A sankey (its node and link values) and a butterfly or a pyramid (both sides together, so a row reads at one magnitude) print their values at one magnitude, as the funnel does: the largest step at which the smallest value still prints as 1 or more, while the largest keeps at most four digits. So `1,505M · 935M` instead of `1.505B · 935M`. A butterfly side with its own unit or format is its own set. A set that no single magnitude fits keeps one scale per label as before. A value that prints 1,000 or more at the set's magnitude prints whole. Decimals and shares print as before. No option or theme patch brings back the old look for every chart. A chart `format` holds every label to the scale of its example, for example `"format": "1.2B"`.
- Render, `measure`, `canDraw` and React name the same minimum width for a width alone, found by one search over the layouts render draws, its steps after a refusal included (authored column widths giving way, type stepped down on a slide, the next smaller type class). `minWidth` is the narrowest width from which every wider width draws in full mode, `compactFloor.width` the narrowest from which every wider width draws at all, and a size refusal names the width at which the request starts to draw under its own `belowMinimum`. Before, these could differ: a table at 280 px was refused with 1208 px in render and `canDraw`, `measure` said 1057 px, and the table drew from 1024 px. `measure` named a `minWidth` where render falls back to compact (a two-panel bar table: 367 px, full from 451 px), a `compactFloor` above the width a column draws from (280 px for a slide column that draws from 125 px), and no `compactFloor` for a waffle that draws compact. A table's and a dimswitch's refusal now reads like every other type's ("needs at least N px of width"). A dimswitch refusal names the height drawn at that width, where `measure` named the height of the folded card (at 280 px: 551 px, before 224 px). CLI `measure` no longer draws each advised size a second time; it confirmed every size the core named. A chart that draws keeps its output.
- Column: a plan tick (a reference series drawn as a tick) now draws behind its column and reaches up to 4 px past each side (2 px where a plan value beside it needs the room), in place of 2 px over the column on a page-colour band. The band cut a light line through every column above its plan, and a tick a few pixels under the column's top read as a second edge. A column short of its plan now prints its value inside its end at every distance to the tick, so every such column takes one seat. A tick beside its column (the integrated PY tick of a stacked column) is unchanged.
- To bring back the earlier look, tick and value seats alike, set `referenceTick: { position: "front" }` on the column chart (or on each column panel of a grid).
- On a column chart with one reference series (a plan tick) that the key names, a reference value that is too wide for the gap beside its column prints the number alone ("400", not "400 Plan"), for every value of that series. Before, at narrow widths such as 360 px, the named values found no seat and all went to the notes. `{ "labels": { "tick": ["absolute", "series"] } }` brings back the old text.
- A reference value no longer takes the seat left of its tick when the column to its left has a value of the same series, where it read as that column's value.
- An MCP render with `format: "png"`, `outDir` and `return: []` sends no image block: the answer names the written files in `outputs` and no longer repeats the PNG bytes as base64 (about 296 KB for one map). A call without `return` still returns the image block.
- The React table (`TableChart`, and `DimSwitchChart` through it) now takes tighter spacing before it scrolls sideways, as the SVG table does. A table wider than its box steps down the table's fit ladder (12 px side margins, 6 px and 3 px cell air, heads on two lines, compact density, tight spacing) and draws the first rung at which it fits without scrolling. Before, the grid always drew full spacing (12 px cell air, regular density) and scrolled. A table that fits at full spacing draws as before, and a table that fits at no rung still draws full spacing and scrolls with its `table-overflow` advice. To keep the old look, give the table a frame at least as wide as the old `table-overflow` advice.
- `labels.valueLine` on a chart that labels each valueLine annotation itself (line, for example) is still refused, and the refusal now names `label: false` on each `{ kind: 'valueLine' }` annotation, with a fix that sets it. A `footnote` on a metric-stack category is still refused, and the refusal now names `options.footnotes` and the partial-period footnote.
- Four refusals now name the setting that does the job. A dimswitch without its range or prior period names `options.columnVisibility` to hide that column. An invalid table status names `{ state: 'na' }` for a status that cannot be decided. Rows without a series column say to add one with the same series name on every row. An unknown theme name lists the themes whose name holds it first, so `dark` names `bridge-dark`, `standard-dark` and `notation-dark`.
- Render warnings are shorter, and two frequent layout checks no longer ask for a review. `height-off-ladder` (an authored height between the standard height steps) is now `advice`, was `warn`, with a shorter message. `dead-band` (an empty band on the canvas) is now `advice`, was `warn`; it suggests removing a margin only where the spec sets one on that edge. `height-off-ladder:row-driven` (`info`) is no longer reported: a type whose height comes from its rows has no standard step. `values-in-note` keeps `info` and states the count; each value is now only in `detail.values`, no longer also in `message`. A finding without an expectation of its own no longer copies its `suggest` or `message` into `expected.condition`; `expected` is then `{}`. The MCP server returns them with every chart that has them: its once-per-session rule now covers only the `design-*` advice. `render --quiet` no longer prints them.
- The React table takes its frame text from the same core function as the SVG frame. Its subtitle uses the core unit clause: no "in $M" after a measure that already names the unit, and the ratio wording ("Coverage ratio (×)"). A table without a subtitle prints its declared unit where the subtitle goes when no head, cell, note or source carries it, as the SVG does; `unitShown: true` turns that line off.

### Fixed

- Line charts, including area and bump variants, and plain slope charts ignore unsupported highlight IDs before choosing colours, markers and label priority. Category IDs and reference-series IDs now warn `highlight-unknown-id`, as unknown IDs already did. A valid series highlight in the same list still works. Valid inputs keep their previous appearance.
- An `abs` annotation without its own format prints the value as the anchored mark's label does on combo, bar and dot: "4.1%" beside a "4.1%" line label (it printed "4.1"), and "4.12" beside a "4.12" bar label (it printed "4.1").
- `render --quiet` and a repeated MCP render no longer lay a chart out a second time for a design advice they do not print (the direct-label advice of a line chart, the horizontal advice of a waterfall). The answers are the same; the render does half the layouts for such a chart.
- The size advised in a `table-tight-spacing` or `plot-under-floor` patch now holds: the chart drawn at that size does not warn again. A tight-spacing patch names no height where the caller left the height open. `measure` lays the table out at the advised size until it stops tightening, and render checks a table's advised size once at that size. Plot advice for a pinned height that moves asked notes (`methodNote`, `notes.placement`) to the notes list is measured with those notes, as the advised height draws them.
- A refusal about one annotation points at the annotation the author wrote. Before, a chart that does not draw some annotation kinds counted the index after it dropped them, so a scatter with `[indicator100, valueLine -1]` on a log axis returned `/annotations/0` and the indicator. A list under `options.annotations` was pointed at as the root list, and several line, event and Gantt refusals had no pointer. A grid panel's annotation refusal points into `data.panels[i]`. The `x-cagr-unsupported` and butterfly `delta-column-covers-annotation` warnings point at the annotation the same way. ### Changed / may need action

The default design system is now Bridge. The light default changes from `boardroom` to `bridge`. The dark pair changes from `standard-dark` to `bridge-dark`.

Bridge uses navy ink, one cobalt accent and a slate neutral. Its categorical colours run in this order: navy, blue, slate, ochre, plum, teal, orange and violet. Every data mark of the Bridge colours has at least 3:1 contrast on its page. Background fills (the waffle remainder, bar and range tracks, and Others) are pale on purpose and stay behind the data. Status and Gantt colours stay apart in greyscale. Titles are semibold. Stacks use a four-step blue ramp.

Use `theme: "boardroom"` for the old light look or `theme: "standard-dark"` for the old dark look. A spec can also set `"theme": { "preset": "boardroom" }`.

`bridge-dark` is a dark-scheme preset that a host passes itself. The preset does not switch automatically.

- An area spark on a KPI card now starts its scale at zero, as a column spark does. Before, the floor was the series minimum: ARR that rose 50%, from 1.21bn to 1.82bn, filled from nothing in January and read as growth from zero. The wash now fills to zero, and a series below zero fills up to the zero line. A line spark keeps its min-max range. A theme with `surface.sparkWash: false` draws an area spark as a line and keeps the min-max range too. Table cells draw only line and column sparks, so table cells do not change. To bring back the old look, set the theme override `{ "surface": { "sparkAreaBase": "min" } }`.
- The average marker of a column, bar or combo chart now leaves out categories marked `partial`, such as a week still running. Its label names the periods it covers, for example `Average 674.4 (W31–W37)`. A mean that mixed a running total into finished ones was too low. The new option `averageMarker: { includePartial: true }` brings the old mean back. `averageMarker.scope` is now optional, so `{ includePartial: true }` alone averages every series. A chart whose categories are all partial still averages them.

A series whose cells all carry one scenario counts as that scenario. PY draws the actual's colour as the 45 % wash toward the page, FC hatches it and PL outlines it. Series order no longer changes the colours. A PY cell in a series of several scenarios draws the same wash. In a stack only a plan pairs: its outline takes the colour of the k-th plain segment. ## 0.53.0

### Added

- Gantt takes `options.calendar`. `calendar.weeks: 'startDay'` names each week cell by the day of the month it starts on ("9"), flush left under the month tier, in place of the ISO week number ("W11"). It applies at week granularity only; elsewhere it is ignored with the info lint `calendar-weeks-ignored`. `calendar.span: 'data'` runs the timeline from the first item to the later of the last item end and `today`, in place of whole calendar periods, so arrow tips meet the edge. The head's scale follows that span. A milestone or cadence marker on the first or last day keeps room for its radius (up to 8 px) inside the edge, at any width. Weekend bands count from the Monday on or before the span start. The defaults (`'isoWeek'`, `'periods'`) keep the current head. The `status-timeline` fixture uses both.
- Gantt `rows[].sublabel`: a second line under the row name, such as what the row measures. It prints in the label font and muted ink, on one line and never cut. The name band takes the wider of the name and the sublabel, and the name and sublabel centre together on the row. On narrow canvases (the stacked form) it follows the name on the row's name line. `labels.activity: false` hides it with the name. A row whose wrapped name and sublabel need more than the row pitch grows to fit them. The accessible row summary and the item and cadence event records read "name, sublabel". New example fixture `status-timeline`.
- Gantt items take `kind: 'rule'`: a quiet span for the state before a change. It draws a 2 px neutral line on the bottom edge of the bar box, with its label 2 px above the line in muted ink, flush left. The line is a data mark and never breaks around text. A rule never takes a colour or a colour-key entry; `colorRole` or `colorLabel` on a rule is refused. The `status-timeline` fixture uses it for the states before each change.
- Gantt events take `labelPlacement: 'badge'`: the label, at most 3 characters such as a change number, sits in a filled circle at the top of its rule, and the rule starts 2 px under the circle. The circle is ink, or the bad colour for `tone: 'bad'`. Its text takes the ink that reads on the circle in the active theme. Badges stack in their own strip above the event names, numbered rings and today label, so adding a badge hides none of them. Without annotation labels no badge is drawn and the strip takes no height. Badge events never go to the numbered footnote key and do not count toward the key mode above three events. Badges closer than their width plus 4 px stack one level up. A longer badge label is refused, and column and combo refuse `'badge'`. The `status-timeline` fixture numbers its three changes with badges.
- Rows for `table` (alias `tbl`): `boardplot render` and `boardplot measure` with `--rows`, `boardplot_render` and `boardplot_measure` with `rows` or `rowsFile`, and `specFromRows` from `boardplot/rows` fill `data.rows` from a flat table, one source row per table row. The spec's `data.columns` declares the columns, with no inference from the rows: each `value`, `text`, `status` or `date` column reads the source field named like its id, and `computed` and `encoding` columns keep their definitions. Two optional column roles: `label` fills the row label that the `rowLabel` column shows, and the new role `id` fills the row id (default `row-1`, `row-2`, ...), as in `--columns label=region,id=code`. Rows keep source order. A spec row with the same id keeps its authored fields, such as `role`, `parentId`, `calc` or `format`. A table column with no source field, text that a value column cannot read as a number, a boolean cell, an empty or repeated row id and a `valueKind` other than `number` are refused with the source row and field; a refusal or warning of the table engine about a source cell, such as a status it refuses, names the source row and field too. A repeated spec row id, a nested spec row with another `parentId`, and a drawn row whose `parentId` or `calc` names a spec row that no source row provides are refused at the spec field.
- Rows for `histogram` (aliases `distribution`, `frequency`) and `box` (aliases `boxplot`, `box-and-whisker`) in `boardplot render` and `boardplot measure` (`--rows`), `boardplot_render` and `boardplot_measure` (`rows`, `rowsFile`) and `specFromRows`: one source row per observation. Histogram takes the role `value`. Box takes `category` (the group id) and `value`, and optionally `categoryLabel` and `date`; groups keep their first appearance, and a group the spec already names keeps its other fields. A null, blank, non-numeric or non-finite observation is refused with `missing-value` or `invalid-value` and its source row and field, never dropped; a group with two labels or two dates, a group label or date that is not text (`invalid-value`) and a repeated spec group id (`invalid-data`, at the spec path) are refused; `valueKind` other than `number` is refused. A histogram still needs four observations.
- React: `onRowSelect(rowId, { row, event, columnId })` and `isRowSelectable(row, { collapsed })` on `BoardplotChart`, as `TableChart` takes them: a click in a table row or Enter or Space on its focused cell calls `onRowSelect`. Only a `table` spec (alias `tbl`) receives them; `BoardplotChart` passes them to no other chart type, so they never reach a chart's options. A `dimswitch` spec draws as SVG in `BoardplotChart` and takes no row pick; `DimSwitchChart` from `boardplot/react/dimswitch` keeps its own `onRowSelect`.
- React: `onSpecError(errors)` on `BoardplotChart`. It is called after commit with the findings `SpecErrorCard` shows, for an invalid spec or setting and for a chunk that did not load (`chunk-load-failed`), so a host no longer looks for the card in the page. It is called once per distinct set of findings: a rerender with the same findings, a host that sets state from the call, and StrictMode's repeated effects call it no second time. It is called once with `[]` when a later valid spec replaces the error card (its chart engine is ready, or its data is empty), without waiting for the chart to draw, because a valid spec can still wait for its container or refuse its size. Empty data stays on `onEmpty`, and a layout refusal on `onRefused`.
- Boardplot for Python in `python/`. `bp.chart(df, ...)` draws the same SVG as the CLI in a notebook or a script without Node, and `bp.st_chart` draws a chart in Streamlit. It is not on PyPI yet.

### Changed / may need action

- Gantt event rules and the today line give way to span names. A bar, arrow or shade name that has no seat clear of the rules now sits inside its own mark across them, and each crossed rule breaks over the full height of that mark. A seat clear of every rule still wins; each crossed rule adds 1 to a seat's penalty. Before, the rules blocked these names, which went to the notes list, so a long arrow name across two event rules was hidden below about 1,800 px. There is no option to bring the old behaviour back: it only ever hid labels. Milestone and bracket labels keep the rules as obstacles. The today line now keeps 2 px instead of 1 px above and below a label it breaks for (`torture-long-labels`).
- `gantt-arrow-label-hidden` suggests "increase chart width or shorten the arrow name". Height never gave an arrow name room.

### Fixed

- Percent cells (`{ pct }`, `valueKind: 'percent'` or `'fraction'`) keep their percent sign on bar, dot and funnel value labels ("70%", not "70"), as on column. This covers the centered funnel and a bar's Rest built from percent cells. A value axis whose values are all percent cells prints "%" on its ticks too, on line, column, bar and dot. An authored `format` on the chart, series or cell keeps winning; `options.format: '0'` brings back the bare numbers.
- A percent mekko of authored shares with no amount in the column (no number cell, no `total100`) prints no column total. Before, it printed "0" above segments that read 70% and 30%. The totals row, the `derived.columnTotals` entry and the totals sentence of the description leave such a column out. Number cells keep their totals.
- A `bartable` draws from rows (CLI `--rows`, MCP `rows` and `rowsFile`, `specFromRows`). Before, it was refused with `invalid-data` at `/data/panels`. The categories become the table rows, the series the bar segments, and the value column fills one panel. The spec's first panel is the template for that panel. Its `ends`, other panels and number `columns` are dropped, because they hold one value per authored row. Percent values fill the panel as plain numbers with the unit `%`. One panel adds its segments, so rows with two units, percent values beside plain numbers, or a value cell with more than its number (such as a `format`) are refused at their row.
- Data ids named like `Object.prototype` members (`__proto__`, `constructor`, `toString`, `hasOwnProperty`, `valueOf`) draw like any other id. Before, a category, series, stage, slice or column with such an id printed wrong values (`n.m.`, `+n/a`, a missing table cell, "on target" instead of the real gap), dropped box ticks and labels, or refused with a wrong cause (waterfall `label-collision`, pie `invalid-size`, pareto `invalid-number`). Keyed values such as table `cells`, bartable `values`, pie `explode`, dimswitch `sums` and grid `bySlice` now keep a `__proto__` key, and a grid repeat value `__proto__` is no longer refused. Detail keys still refuse `__proto__`.
- Gantt `rows[].cols`: a cell object's `tone` is optional, so `{ "text": "x" }` is valid and means the same as `"x"`. Before, it was refused with a missing-tone error.
- Schema errors of a union with a literal tag: when one branch fails on its own tag (a gantt task row checked against `kind: 'cadence'`) and another branch has no error at that tag and fails on a field that is present, only the second branch's errors are reported. A branch that only misses a field never hides another branch's errors. Identical errors (same path and message) are reported once. Before, a task row with one bad item kind reported the item error plus a misleading "expected cadence" error, and a bad `cols` cell was reported twice. No golden changes.
- Gantt event rules at an ISO date or at a bar, chevron, bracket or shade item draw on the start edge of their day. An event at an item id now sits exactly on that item's start edge, the boundary it marks. Before, the rule sat half a day inside the new span. An event at a milestone or a cadence event keeps drawing through the middle of its marker. The today line stays at the middle of its day. No golden changes: the only fixture with events anchors them at cadence events.
- Text measurement gives default-ignorable code points (soft hyphen U+00AD, zero-width space, ZWNJ and ZWJ on their own, word joiner U+2060, BOM U+FEFF) no width and no letter-spacing step, with the bundled tables, host tables and the character-class model alike, also when a combining mark follows one. Browsers draw them invisible. The Hangul fillers (U+115F, U+1160, U+3164, U+FFA0) and the shorthand format controls (U+1BCA0 to U+1BCA3) keep their width, as browsers draw them. Wrapping keeps a BOM inside its word instead of breaking there as at a space. Before, a host table could give a soft hyphen a width, and `boardplot fonts build` wrote a negative variable-font advance as about 65 em, so a label with a soft hyphen measured far wider than it drew. `fonts build` now writes a negative advance as 0; rebuild host tables made with an earlier version. No golden changes.
- Number format examples and `rgba()` alpha colours no longer slow down on long malformed input. A format of 50,000 characters took 1 to 2 seconds to parse, and a chart parses its format about 16 times per render. Valid formats and colours parse to the same result.

## 0.52.5

First public release.

- 37 chart types from one JSON spec, among them bar, column, line, waterfall, mekko, scatter, tables, Gantt charts and maps.
- Output as deterministic SVG, as PNG and as React components; the same spec gives the same SVG, byte for byte.
- One collision solver places every label. A chart that does not fit is refused with the size it needs.
- Totals, differences, shares and growth rates are computed from the data, and each render reports them.
- Four targets (`report`, `dashboard`, `slide`, `print`) set the type sizes for the medium.
- Theme presets, custom themes and contrast checks; width tables for Geist, Helvetica and Arial (Helvetica Neue is measured with the Helvetica widths), and `boardplot fonts build` for a licensed font.
- Map packs for the world, Europe, the EU-27, the US states, the DACH countries and the German states.
- The `boardplot` CLI and the `boardplot-mcp` server with six MCP tools: list, describe, fixtures, measure, render and feedback.
- A plugin for Claude Code and Codex with a chart skill and the bundled runtime.
- Complete example specs (fixtures) for every chart type.
