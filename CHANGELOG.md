# Changelog

Boardplot is in 0.x: options and output can change between minor versions. Each release lists its changes here.

## Unreleased

### Changed

- The default Likert ramp now clears its own adjacent-colour floor, so it no longer warns `series-adjacent-similar`. Two neighbours moved. The neutral grey keeps 12 OKLab from the mildest option beside it on a light page too, not only on a dark page: in `bridge` it is `#d5d9e5`, before `#d4d8e4`. Where no neutral is drawn between the two sides (`neutral: 'exclude'` or an even scale), the mildest good option steps until it keeps 12 OKLab from the mildest bad one: on a seven-point scale with `neutral: 'exclude'`, it is `#9fb8df` in `standard-dark` (before `#acc6ef`), `#aeccf9` in `bridge-dark` (before `#b4d0f9`) and `#a1b7dd` in `notation-dark` (before `#adc4ed`). Each colour moves only as far as the floor needs, and a ramp that cleared the floor draws as before. No option brings back the old colours.

## 0.57.0

### Added

- `highlight` accepts category IDs on one plain data line without a fan. For example, `{ "options": { "highlight": ["w5"] } }` enlarges W5's marker and paints its marker and value in the theme's focus ink while the line keeps its paint and width. The marker size follows the theme's focus-to-data stroke ratio. Existing series emphasis, authored marker shapes and fills, and explicit label suppression remain effective. Reference series do not count as data lines. Several data series, area, stacked, bump and fan forms still warn once for unsupported category IDs and leave the chart unchanged. Series IDs take precedence. Remove the category ID from `highlight`, or use `{ "options": { "highlight": [] } }` when it is the only selection, to restore the ordinary marker and value.
- `columnOverrides` on bartable, heatmap and status sets the width, alignment and head text of one column, for example `{ "columnOverrides": { "label": { "width": 170, "align": "left" }, "fy": { "width": 150, "label": "Full year", "headAlign": "right" } } }`. The ids are `label` and the column ids of the data: `data.columns` and `data.panels` on bartable, `data.categories` on heatmap, `data.columns` on status. A width beats a panel `weight`. Under `sharedScale` or a cascade a panel width warns `option-ignored`. A width too wide warns `generated-column-width-capped` and a width too narrow warns `generated-column-width-floored`. A width that would refuse the chart, drop or reword a printed text, or newly cut a label gives way to the unset width with the same warnings. A head alignment that would hide a head gives way and warns `option-ignored`. On the row names, `label` and `headAlign` refuse with `invalid-options`, because they print no head. A panel `align` aligns the panel head, and a new head text also reaches the hover and the records.
- `columnOrder` on bartable moves the blocks `numbers` and `panels`, for example `{ "columnOrder": ["panels", "numbers"] }`.
- `columnHeads: false` on bartable drops the head row with its height and rule, for example `{ "columnHeads": false }`.
- `totalPosition` on bartable puts the Total row at the `top` or `bottom`, with its rule and ground, also under a cascade, for example `{ "totalPosition": "top" }`.
- `labels.point: false` on bartable stops the values in the segments and at the bar ends, for example `{ "labels": { "point": false } }`. Number columns, shares, growth and the Total row keep their numbers.
- `columnVisibility` on cohort exhibits leaves the size column out, for example `{ "columnVisibility": { "size": false } }`. The bases stay in the weighted total and the printed average bases. It warns `cohort-size-hidden`, because a reader loses the cohort sizes.
- `columnOverrides` on cohort exhibits sets the width, alignment and head text of the tracks `label`, `size` and `periods`, for example `{ "columnOverrides": { "label": { "width": 190, "label": "Signup month" }, "periods": { "width": 80, "align": "right" } } }`. A `periods` width is per period column, replaces the shared width, and leaves spare room empty on the right. `label` on `size` beats `cohortSizeLabel`. `label` on the `label` track sets the corner head and warns `cohort-unit-unprinted` where the corner was the only place that named the unit. `label` on `periods` warns `option-ignored`. A width never refuses and never removes a period: it gives way with `generated-column-width-capped` or `generated-column-width-floored`. A long head text wraps, then is cut, where its room would cost a period. A center or right `headAlign` on a corner head too wide for its track warns `option-ignored`, because the head starts at the table edge.
- `columnOrder` on cohort exhibits moves the blocks `size` and `periods`, for example `{ "columnOrder": ["periods", "size"] }`.
- `columnHeads: false` on cohort exhibits draws no period heads, size head, corner, head rule or range lines, with their height and width, for example `{ "columnHeads": false }`. It always warns `cohort-heads-hidden`, naming the periods, the unit and the key's numbers where the heads carried them.
- `totalPosition` on cohort exhibits puts the summary row at the `top` or `bottom`, with its ground, rules, gap and average bases, for example `{ "totalPosition": "top" }`.
- `designatedPeriod: false` on the pure cohort exhibit draws no column tint and no head emphasis, for example `{ "designatedPeriod": false }`.
- `figures: false` on the stepped cohort exhibit stops the numbers on filled cells, for example `{ "figures": false }`. Cells with no fill keep their text, including period 0. Hover, records and accessible values stay.
- `total` on the cohort heatmap: `false` hides the average row, `'weighted'` equals `averages: 'weighted'`, and `total` wins when both are set, for example `{ "total": "weighted" }`.
- `visiblePeriods` on the cohort heatmap hides periods, for example `{ "visiblePeriods": [1, 2, 4] }`. Rates and averages are still derived over all periods. A hidden period leaves no cell, head, note, key item, count, record or claim.
- The exhibit keys refuse on the heatmap variant, `figures` refuses off `stepped` and `designatedPeriod: false` refuses off `pure`, in the schema and in React.
- A creative card sets its metric table through `options.columnOverrides`, for example `{ "label": { "width": 120, "label": "Metric" }, "delta": { "align": "left" } }`. Each column takes `width`, `align`, `headAlign` and `label`. Charts without this setting draw as before.
- A creative card can leave out columns: `options.columnVisibility` takes `{ "median": false, "delta": false }`. Hiding delta also drops the colour key, and the period sentence names only the columns drawn. `label` stays.
- A creative card can leave out, reorder and rename metric rows: `options.rowVisibility` takes `{ "frequency": false }`, `options.rowOrder` takes `["roas", "ctr"]` and `options.rowOverrides` takes `{ "roas": { "label": "Return" } }`. Medians and fatigue still read all six metrics, a hidden metric does not count as missing, and a hidden row or column leaves the records and the hover card.
- A creative card can drop its table head and reorder its columns: `options.columnHeads` takes `false` and `options.columnOrder` takes `["label", "delta", "value", "median"]`.
- A choropleth lookup table sets its columns through `options.columnOverrides`, for example `{ "code": { "width": 96 }, "value": { "label": "Revenue", "align": "right" } }`, and `options.columnVisibility` leaves out `swatch` or `value`, for example `{ "swatch": false }`. `code` stays. Hiding `value` also drops the unit caption and warns once. `label` and `headAlign` work on `value` only, because only that column prints a head. A width that does not fit is reduced and warns.
- A choropleth lookup table can leave out, reorder and rename rows by region id, through the map pack's aliases: `options.rowVisibility` takes `{ "DE-HB": false }`, `options.rowOrder` takes `["DE-BE"]` and `options.rowOverrides` takes `{ "DE-BE": { "label": "Capital" } }`. The map still draws every region. The table's size limit counts the rows drawn.
- A choropleth can turn off its top-group bold: `options.valueTableEmphasis` takes `"top"` or `false`. `false` also unbolds the map labels. The top group ranks all regions, also hidden rows.
- A sankey can drop the values at its nodes: `options.nodeValue` takes `false`. Marks, hover and records stay.
- A sankey sets the gutters of its first and last stage through `options.columnOverrides`, for example `{ "first": { "width": 90 }, "last": { "width": 120 } }`.
- A horizontal waterfall and the horizontal form of a pvm set their name and value bands through `options.columnOverrides`, for example `{ "label": { "width": 220 }, "value": { "width": 80 } }`. An explicit `variant: "vertical"` refuses this key. A chart that draws vertical without that setting warns `option-ignored`. The key never changes which variant is chosen.
- A pvm can drop its bar values: `options.labels` takes `{ "point": false }`. The net change stays on its own switch, `netChange`, and takes the seat of the total. Marks, hover and records stay.
- A diagram inset can drop its heading and set its columns: `data.inset.heading` takes `false` and `data.inset.columnOverrides` takes `{ "label": { "width": 90 }, "value": { "align": "left" } }`. The accessible name stays. `label.align` and `value.align` give way with `option-ignored` where the chart lacks the height.
- A dimswitch can leave out its Range, vs prior and vs plan columns: `options.columnVisibility` takes `{ "range": false, "pp": false, "pl": false }`, the same column ids as `options.encodings`. The label column and the period columns close up with no gap, and sticky columns count only the columns drawn. A note or claim about a left-out column does not print. The data still needs its range and prior periods, and `order` and `show` still read Range. Charts without this setting draw as before.
- Dimswitch `columnVisibility` also takes period ids, so a table can show Range alone: `{ "columnVisibility": { "pp": false, "w1": false, "w2": false } }`. The label column stays. Hiding every value column draws the labels and warns `dimswitch-labels-only`.
- React `DimSwitchChart` reads `defaultColumnVisibility` as `columnVisibility`, the controlled prop wins, and an exported document keeps the state: `<DimSwitchChart defaultColumnVisibility={{ w1: false }} />`.
- Dimswitch `columnOverrides` sets `width`, `align`, `headAlign` and `label` on `label`, `range`, `pp`, `pl` and each period id: `{ "columnOverrides": { "label": { "label": "Metric" }, "w2": { "width": 120 } } }`. A width beats `widths`. The automatic card form sizes value tracks by content and warns `option-ignored` on such a width.
- Dimswitch `columnOrder` orders the `block` and `periods` blocks after the label: `{ "columnOrder": ["periods", "block"] }`. Only the label and leading block columns pin.
- A dimswitch can turn its automatic size bars off: `{ "bars": false }`. Scale, precision, data and judgement stay. A table that draws no bars warns `option-ignored`.
- A dimswitch can leave out its Total or its group heads: `{ "rowVisibility": { "total": false, "group:Unit costs": false, "group:": false } }`. The ids are `dimension.total.id`, `group:<measures[].group as authored>` and `group:` for the ungrouped section. In by-member the whole Total block goes. In by-measure each Total line keeps its label and folds with blank cells, because it carries the KPI name and owns its members. A hidden Total keeps the magnitude and decimals that members print with it, but where `widths` make a track narrow, format fitting follows the table as drawn, so a member can print 17.5% where the chart with the Total prints 18%. A table with no value left warns `dimswitch-labels-only`, and an id the table does not draw warns `generated-id-unknown`. Neither refuses.
- `totalPosition` now works on a by-member dimswitch: `{ "variant": "by-member", "totalPosition": "bottom" }` moves the Total block after the last member. In by-measure, and where `rowVisibility` hides the by-member Total block, the key warns `option-ignored`.
- A gantt can set each column: `options.columnOverrides` takes `name`, `meta0`, `meta1` and `meta2`, each with `width`, `align`, `headAlign` and `label`, for example `{ "name": { "width": 180, "label": "Workstream" }, "meta0": { "align": "right" } }`. `label` beats `colHeaders` for that column. A width under the text stops at the text and a width that leaves too little timeline gives way, and both warn. A wide width also stops at the widest width that hides no label the chart without it prints. On a canvas that cannot grow, a `name` width whose wrapped rows miss the height gives way to the narrowest name width that fits, and warns. A column with one of these settings shows its values in full. The stacked form draws where the columns do not fit or where the table form would hide a label the chart without the setting prints. It has no columns, so it reads only `label` and warns about the rest.
- A gantt can put its metadata on the far side of the bars: `options.columnOrder` takes `meta` and `plot`, for example `["plot", "meta"]`. The name column stays first. The stacked form ignores the order with a warning.
- A metric stack can leave out parts of its readout: `options.stack.columnVisibility` takes the gutter's seats `unit`, `headline` and `span`, for example `{ "unit": false, "span": false }`. A hidden part leaves no claim or reserved height, the method line names only the figures that print, and hiding both figures drops that line. The panel name stays.
- A metric stack can size and align its readout gutter: `options.stack.columnOverrides` takes `{ "gutter": { "width": 200, "align": "right" } }`.
- A metric stack can put its readouts right of the plots: `options.stack.columnOrder` takes `gutter` and `plot`, for example `["plot", "gutter"]`. Above the panels on a narrow canvas both gutter settings warn and do nothing.
- A table can draw no head: `options.columnHeads: false` removes the head row and the group headings, with their height, rule and sticky offset, and no head widens a column. `{ "columnHeads": false }`. The SVG draws no head. React keeps a visually hidden head for assistive technology and warns `column-heads-sortable` when `sortable` is set, because the sort controls live in the head. A unit that only the head printed warns `column-heads-unit-hidden`. A dimswitch takes the same key, and its partial star leaves with the head while the note stays.
- A table column can align its head apart from its cells: `data.columns[].headAlign` takes the values of `align` and falls back to it. `{ "id": "fy25", "kind": "value", "align": "right", "headAlign": "left" }`.
- `columnOverrides` on `bullet`, `dot`, `likert`, `butterfly`, `slope`, `kpi`, `pyramid`, `box`, `funnel` and `bar` sets a column's `width`. A wide width takes room from the plot first and stops at the plot floor with a warning. Nothing refuses because of a width. `{ "columnOverrides": { "label": { "width": 200 } } }`
- `columnOverrides` also takes `align` on `bullet`, `butterfly`, `dot`, `kpi`, `likert`, `pyramid` and `slope`, and it beats `rowLabels.align`. `{ "columnOverrides": { "label": { "width": 180, "align": "right" } } }`
- `columnOverrides` takes `headAlign` and `label` on the types that print a head. `{ "columnOverrides": { "gap": { "label": "To plan", "headAlign": "left" } } }`
- `butterfly` `columnOverrides.label.width` beats `centerColumnWidth`. `{ "centerColumnWidth": 120, "columnOverrides": { "label": { "width": 160 } } }`
- `bullet` `columnVisibility` leaves out `actual`, `share` and `delta` under `percentOfTarget`, and `target` and `gap` with the target columns. An id the current form does not draw warns with the list. `{ "columnVisibility": { "share": false } }`
- `bullet` `columnOrder` moves `actual`, `share`, `delta`, `target` and `gap` around `plot`. `{ "columnOrder": ["target", "gap", "plot"] }`
- `bullet` `labels.position` and `labels.direction` drop the "below target" and "higher is better" lines on their own. `labels.annotation: false` still drops every line. `{ "labels": { "direction": false } }`
- `likert` `columnOrder` moves `net` and `base` to the other side of the marks. `{ "columnOrder": ["net", "plot", "base"] }`
- Table and dimswitch `paintOffscreenRows: true` paints every mounted row at once, so a capture of a long table has no blank rows. It turns off the deferred paint and the row paging over 500 rows. A long table paints slower, and closed rows still follow `mountCollapsed`. Example: `{"options": {"paintOffscreenRows": true}}`. The host CSS workaround in the docs is no longer needed.
- Table and dimswitch `rowLabelLines` takes any positive whole number, not only 1 or 2. Track widths, row heights and the React grid follow the count. Example: `{"options": {"rowLabelLines": 3}}`.

### Changed

- Point values on one plain data line now prefer left of the first finite point, above a strict local peak, below a strict local trough and right of the last finite point. The new `pointLabelSide: "shape"` default reserves space for endpoint values beside their points only where the plot can spare it. The reserve is not used when the centred end room cannot print every category name, or when the reserve would print the category names differently. If a layout with the reserve hides any label, the chart is laid out again with the centred end room. It keeps the reserve only if every label of the centred layout still prints. Flat plateaus keep the previous preference. Reference series do not count as data lines. Several data series, area, stacked, bump and fan forms keep their previous placement. The label solver still checks collisions and honours `labelPlacements` pins. A reference line through a preferred seat blocks that seat. The solver uses the next candidate without cutting the reference line around the value. To restore the previous candidate order and endpoint reserves, use `{ "options": { "pointLabelSide": "auto" } }`.
- Shaded-band names now try seats within the plot before seats beyond it. The plot includes reserved annotation headroom. Seats within the plot keep their previous order, so a clear name above a band stays there. A name that would leave the plot can instead wrap inside. Previously, the one-line `aboveBand`, `aboveBandEnd` and `aboveBandStart` seats preceded extended inside seats even when outside the plot. To restore the previous outside seat in the narrow maintenance example, use `{ "options": { "labelPlacements": { "annotation:maintenance": "aboveBandEnd" } } }`. For the same band as the first annotation without an explicit ID, use `{ "options": { "labelPlacements": { "annotation:band-1": "aboveBandEnd" } } }`. Use the band's own annotation ID and previous slot for other bands. Pins keep their previous candidate order and collision fallback. Bracket bands keep their placement order.
- `boardplot_describe` in compact detail names the accepted shared options and defines value cells and annotation anchors where a type uses them, so a known type needs no `boardplot_list` call. Full detail keeps the type's own fields with complete descriptions; shared options stay names, and `path` returns one in full.
- MCP output schemas declare the chart reading, `severity` and `displayPath` on findings, and the font tables. A file-row error on a category chart now names its source cell in `displayPath`, such as `rowsFile row 1.v`, and its message counts rows from 1, as the other row errors do. Before, it printed `rows[0].v`. A repeated category and series pair names both rows from 1 too, as `(rows 1 and 2)`; it printed `(rows 0 and 1)`. Tool names and arguments stay the same.
- The dimswitch describe example shows a child measure, a computed CAC ratio and the member level.
- The chart skill sends a ready spec straight to render and a known type to compact discovery, and no longer asks for the manual before the first chart. Its references are packaged beside it, so every link resolves in the marketplace and offline ZIP installs.
- A dimswitch with `columnHeads: false` prints its partial Range or period note in the frame, or warns `dimswitch-partial-note-off-frame` where the frame has no place, also where the note would raise the height floor.
- A table's inline line follows the alignment of its column, on a column that is not right-aligned, in the SVG as in React.
- The manual, the README and `boardplot --help` describe the document that draws several charts in one call, `{ "version": 1, "charts": [...] }` with a name per chart: one CLI start for all charts, and one refused chart refuses the call. Before, only the MCP tool description named it.
- Tables and DimSwitch tables lay out much faster, and the speed work does not change a drawing. A table now fits by numbers before it draws and keeps its calculated cells, number formats and measured text between layouts. A DimSwitch keeps its prepared form when Weekly changes is turned on or off. Mean time per layout on a quiet Mac, before this work and now, over a fixed set of open and closed states: the 26-column management report 224.43 ms to 38.27 ms at 878 px and 282.88 ms to 37.94 ms at 332 px, the monthly KPI table with sections 21.21 ms to 18.73 ms and 55.52 ms to 25.06 ms, the weekly KPI table by channel 18.23 ms to 18.01 ms and 109.93 ms to 31.10 ms. The first layout of the management report went from 377.80 ms to 111.60 ms at 878 px and from 434.45 ms to 112.45 ms at 332 px.
- Measurers from `createMetricTablesMeasurer` keep an exact text cache of their own, and the bundled measurer's cache holds 65,536 widths in place of 4,096.
- A DimSwitch keeps the kind of each note when the same data renders at a second width. Before, a disclosure note such as "Week 2 to date" could turn into a method note in the note list. `measure` now reports the larger, correct `minHeight` for a DimSwitch whose note wraps at a narrow width.
- A table or dimswitch render that refuses now names one verified repair width, not the smallest whole-pixel width. Read the width in `fix` and `expected.minimum` as a width that draws, which can be larger than the narrowest one. The message and suggestion wording changes with it, and the warning height follows that width. `measure` still finds the exact smallest width.
- After a table has a fit, `minWidth`, `minHeight`, `comfortableWidth` and `comfortableHeight` in the result sizing and the SVG diagnostics can be larger than before. Read them as the floor of the selected spacing, and use `measure` for the exact floor.
- An automatic table or dimswitch card under 480 px now takes the content height at its own width, so it can be shorter than a wider card. The canvas, background, plot and natural height can drop, and a footer moves up by the same amount. A height that a tight-spacing warning advises follows the new height. Explicit heights and grid panels keep their height. Cell positions, values and fonts stay the same.
- Column `grouped`: `connectors`, `netLine`, `grandTotalLabels`, `shareLabels`, `ribbons` and `seriesLabels` keep their warning and gain a remove patch. These keys stay in the schema, because they work on the stacked variants and can keep a narrow grouped column from stepping to bars. The patch is withheld where removing the key would change the drawing.
- Bump `valueAxis.min`, `max` and `break`, a heatmap `cap` on a discrete scale, and `topN` on `tornado` and `football-field` gain a remove patch on their warning. Over the item budget, `topN` has no patch, because the patched spec would be refused.

### Removed

- `annotations` on bartable, choropleth, cohort, dimswitch, grid, histogram, kpi, sankey, sparkline, status, table, tilemap, treemap and waffle, in `options` and at the chart root, also on a grid panel or repeat template. - `strings.legendCount`, in chart options and on the React provider: no chart printed it. In chart options an old spec still draws and warns `option-deprecated` with a remove patch. The provider drops it without a warning.
- Bar: `baseValue` on every variant but `tornado`, `currentValue` on `grouped`, `stacked`, `stacked100` and `tornado`, `connectors`, `netLine` and `grandTotalLabels` on `grouped` and `tornado`, `averageMarker` on `tornado`, `legend` on `football-field`, and `annotations` and `sort.segments` on `football-field` and `tornado`. An old spec draws the same and warns `option-ignored` with a remove patch.

Cohort: `formatScope` on `pure`, and on the heatmap `sort.categories` and `sort.segments` `asc` and `desc`; `sort.segments: "reverse"` stays.

### Fixed

- Line charts, including area and bump variants, and plain slope charts ignore unsupported highlight IDs before choosing colours, markers and label priority. Category IDs and reference-series IDs now warn `highlight-unknown-id`, as unknown IDs already did. A valid series highlight in the same list still works. Valid inputs keep their previous appearance.
- An unknown option named like another library's axis title (`xTitle`, `yAxisTitle`, `xLabel`, `y_axis_label`) points to `axisTitles.x` or `axisTitles.y` where the type has them, else to `axisTitles`, and a type without axis titles names no near key. Before, `xTitle` and `yTitle` answered "try: title" with a fix patch that moved the axis title into the chart title, and `yLabel` pointed to `labels`.
- A grid of tiers with an open height now keeps the height its parts need. A row-placed grid with long or rotated category names no longer squeezes a tier to a strip: a German-name slide grid at 480 px draws 437 px high instead of 385 px.
- A row-placed tier grid draws at an authored height where it used to refuse, when each tier still fits its own minimum. Slide and print step their type down first, as before.
- On a short canvas, a tier caption no longer prints over the subtitle, and a panel at its plot floor takes height from the panels with plot to spare. The grid warns with `grid-panel-too-short` when the tiers still do not fit. A repair gives way when the plain packing fits and keeps more values.
- Histogram: a long tail no longer makes the default binning refuse its own choice. When the narrower automatic width would need more than 250 bins, as with `[1, 2, …, 10, 400, 1200, 3000]`, `bins: 'auto'` takes the Sturges width and warns `histogram-auto-sturges`, naming an `openAbove` value that gathers the far tail into one open last bin (`bins: { openAbove: 20 }` for that sample). The method note names Sturges. Before, the chart was refused with `histogram-bin-explosion` on `options.bins`, which the author had not set. - Totals, differences, shares and growth rates are computed from the data, and each render reports them.
- Four targets (`report`, `dashboard`, `slide`, `print`) set the type sizes for the medium.
- Theme presets, custom themes and contrast checks; width tables for Geist, Helvetica and Arial (Helvetica Neue is measured with the Helvetica widths), and `boardplot fonts build` for a licensed font.
- Map packs for the world, Europe, the EU-27, the US states, the DACH countries and the German states.
- The `boardplot` CLI and the `boardplot-mcp` server with six MCP tools: list, describe, fixtures, measure, render and feedback.
- A plugin for Claude Code and Codex with a chart skill and the bundled runtime.
- Complete example specs (fixtures) for every chart type.
